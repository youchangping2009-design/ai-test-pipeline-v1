## 2. 需求结论

调用 `giftCardBulkCreate` 创建新一批礼品卡并复用已有标签时，只能把新礼品卡追加到标签关系，不能移除该标签与历史礼品卡之间的关联。连续批次使用相同、部分重叠或完全不同的标签集合后，每个标签都应保留其全部正确礼品卡成员。

## 3. 前置条件 / 准备工作

- 具备调用 `giftCardBulkCreate` 所需权限。
- 数据库中存在至少一批礼品卡和对应标签关系。
- 准备第二批礼品卡创建输入，包括余额、币种、启用状态和标签集合。
- 准备相同标签、部分重叠标签、完全不同标签三类批次组合。

## 4. 业务范围与不做范围

范围内：`giftCardBulkCreate` 对已有标签的关系追加行为；多批次标签组合；新批次返回标签及历史批次标签关系完整性。

范围外：`giftCardCreate` 与 `giftCardUpdate` 行为不变；不新增 GraphQL 字段或数据库迁移；不自动恢复上线前已丢失关系；历史修复依赖商家自身记录。

## 5. 面向研发的需求拆解

- 对已存在标签，将新创建礼品卡加入已有关系，而不是替换该标签的完整礼品卡集合。
- 对新标签，创建标签后关联当前批次礼品卡。
- 一次批量创建的返回数量、错误列表和礼品卡标签结果保持既有接口契约。
- 关系更新应支持批量数量，不引入与历史礼品卡数量线性失控的额外查询。

## 6. 面向测试的验收关注点

- 第二批复用第一批标签后，第一批礼品卡仍保留该标签。
- 两批标签集合完全相同、部分重叠和完全不重叠时，逐标签核对成员集合。
- 新批次每张礼品卡只获得本次输入指定的标签。
- 新标签与已有标签混合输入时，已有关系保留、新关系正确建立。
- 批量创建返回 count 与实际新建数量一致，errors 为空时才视为成功。
- 无权限、非法输入和已有非批量 mutation 不应因本次修复改变行为。

## 7. 数据 / 埋点 / 接口 / 配置要求

- GraphQL mutation：`giftCardBulkCreate`。
- 关键输入：`count`、`balance.amount`、`balance.currency`、`tags`、`isActive`。
- 关键数据关系：GiftCard 与 GiftCardTag 的多对多成员集合。
- PR 未声明新增埋点、配置、API 字段或迁移。

## 8. 风险与兼容性

- 关系替换与追加在单批次中可能都表现正常，必须跨批次检查历史关系。
- 大批量礼品卡和高复用标签可能引入查询次数或关系写入性能风险。
- 并发批量创建复用同一标签时的锁、唯一性和最终成员集合未明确。
- 修复是前向修复，历史已丢失关系不可从数据库自动推导。
