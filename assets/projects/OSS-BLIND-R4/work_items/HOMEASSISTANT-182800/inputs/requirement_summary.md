# HOMEASSISTANT-182800 Prevent duplicate ID3 tags in cached TTS audio 需求整理

整理时间：2026-09-22

## 1. 资料来源

- Home Assistant GitHub PR #182800 的公开描述与合并元数据。
- 本地冻结快照：`inputs/public_source_snapshot.md`。
- 为保持盲测，具体实现、代码 diff、测试夹具和断言不作为需求输入。

## 2. 需求结论

- TTS 音频写标签时，如果 MP3 已有 ID3 标签，应更新或合并为单一标签，而不是追加第二个 ID3 头；已有 TSSE 元数据和音频内容必须保留，缓存落盘后的再次播放应保持可用。

## 3. 前置条件 / 准备工作

- TTS provider 返回已经带 ID3 标签的 MP3，例如 FFmpeg 生成且含 TSSE 的音频。
- 启用 TTS 内存与磁盘缓存，并可覆盖内存项清理后从磁盘读取的路径。
- 准备可识别重复 ID3 头的检查方式和对重复标签敏感的严格解码器。

## 4. 业务范围与不做范围

- 范围内：已带标签 MP3 的标签写入、元数据与音频保留、缓存落盘和后续播放、不同 provider 的一致行为。
- 范围外：重新设计 TTS 缓存策略、改变音频编码、修复第三方解码器，以及未由需求声明的非 MP3 标签格式。

## 5. 面向研发的需求拆解

- 写标签前应识别输入是否已有 ID3 元数据，并使输出只保留一个有效 ID3 头。
- 新增/更新 Home Assistant 所需标签时，不得删除已有 TSSE 元数据。
- 标签处理不得改变音频帧内容。
- 落盘文件与内存首次播放应具有一致的可播放结果。
- 行为不应依赖具体 TTS provider。

## 6. 面向测试的验收关注点

- 已带 TSSE 的 MP3 写标签后仅存在一个 ID3 头，TSSE 仍可读取。
- 写标签前后的音频内容保持一致，严格解码器能够播放输出文件。
- 内存缓存清理后从磁盘读取并播放，结果不应变为静音。
- 未带 ID3 标签的 MP3 仍能正常添加所需标签并播放。
- 对同一文件重复执行标签处理时，不持续增加 ID3 头。
- 至少用两种来源等价的已带标签输入证明行为不依赖 provider。

## 7. 数据 / 埋点 / 接口 / 配置要求

- 关键数据：ID3 头数量、TSSE 标签、Home Assistant 写入的标签及 MP3 音频帧。
- 已知触发窗口：内存缓存项约 300 秒后清理并回退到磁盘文件。
- PR 未声明新增外部 API、配置项、数据库迁移或埋点。

## 8. 风险与兼容性

- 标签版本、扩展头、padding 或异常标签可能影响合并兼容性。
- 只验证播放器返回成功可能漏掉静音，应检查实际可解码音频。
- 处理过程若重编码音频会引入不必要的质量与性能回退。
- 对未带标签输入的兼容路径也可能被标签定位逻辑影响。
