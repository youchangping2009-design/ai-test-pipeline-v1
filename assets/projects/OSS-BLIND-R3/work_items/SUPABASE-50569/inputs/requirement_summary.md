## 2. 需求结论

启用 MFA 且拥有恢复码的用户，在登录后进入 MFA 验证页时，可以选择使用恢复码完成身份验证。有效恢复码登录成功后应消耗该恢复码；功能配置关闭时入口不可见，直接访问恢复码登录页应返回 MFA 验证页。

## 3. 前置条件 / 准备工作

- 用户账户已启用 MFA。
- 用户已生成并安全保存至少两个恢复码，便于验证消费前后数量。
- 用户退出登录后重新完成第一阶段认证并进入 MFA 验证页。
- 可切换 `enableAuthRecoveryCodes` 配置开关。

## 4. 业务范围与不做范围

范围内：MFA 验证页入口、恢复码页面访问、有效恢复码认证、恢复码一次性消费、功能开关关闭后的隐藏与重定向。

范围外：恢复码生成算法、MFA 初次绑定流程、普通密码重置、未在来源中说明的恢复码格式和错误提示文案。

## 5. 面向研发的需求拆解

- MFA 验证页在功能开启且账户具备恢复码时提供【使用恢复码验证】入口。
- 入口打开独立恢复码认证页面。
- 提交有效且未使用的恢复码后建立已完成 MFA 的登录会话。
- 成功使用的恢复码从可用集合中移除，不可重复使用。
- 功能关闭时隐藏入口；直接访问恢复码页面重定向回 MFA 验证页。

## 6. 面向测试的验收关注点

- 有恢复码且开关开启时入口可见并可进入恢复码页面。
- 有效恢复码成功登录，账户安全页可用恢复码数量减少 1。
- 已使用恢复码再次提交不能再次登录。
- 无效、空值或格式不正确的恢复码不得建立登录会话；具体错误文案待确认。
- 开关关闭时入口不可见，直接 URL 访问返回 MFA 验证页。
- 普通 MFA 验证路径在功能开启和关闭时均不回退。

## 7. 数据 / 埋点 / 接口 / 配置要求

- 配置开关：`enableAuthRecoveryCodes`。
- 关键状态：MFA challenge、恢复码可用集合、恢复码使用状态、已认证会话。
- 来源未声明新增埋点、接口字段或错误码。

## 8. 风险与兼容性

- 恢复码是一次性安全凭证，成功认证与消费必须保持原子性，避免并发重复使用。
- 页面路由守卫不能仅隐藏入口，还必须阻止直接 URL 绕过配置。
- 检查恢复码可用性期间的加载或失败状态可能影响入口展示，但来源未定义具体交互。
- 恢复码内容不得出现在日志、URL 或客户端错误上报中。
