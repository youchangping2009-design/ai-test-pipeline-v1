## Top Explicit Rules
- `ER-001` 启用 MFA 且拥有恢复码的用户，在登录后进入 MFA 验证页时，可以选择使用恢复码完成身份验证。有效恢复码登录成功后应消耗该恢复码；功能配置关闭时入口不可见，直接访问恢复码登录页应返回 MFA 验证页。

- `ER-004` 提交有效且未使用的恢复码后建立已完成 MFA 的登录会话。

- `ER-006` 功能关闭时隐藏入口；直接访问恢复码页面重定向回 MFA 验证页。
- `ER-007` 有恢复码且开关开启时入口可见并可进入恢复码页面。
- `ER-008` 有效恢复码成功登录，账户安全页可用恢复码数量减少 1。

## Key Risks
- `RISK-001` [high] 恢复码是一次性安全凭证，成功认证与消费必须保持原子性，避免并发重复使用。
- `RISK-002` [medium] 页面路由守卫不能仅隐藏入口，还必须阻止直接 URL 绕过配置。
- `RISK-003` [medium] 检查恢复码可用性期间的加载或失败状态可能影响入口展示，但来源未定义具体交互。
- `RISK-004` [high] 恢复码内容不得出现在日志、URL 或客户端错误上报中。
