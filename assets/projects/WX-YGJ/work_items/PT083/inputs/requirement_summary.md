## 2. 需求结论

本需求同时改造 C 端云挂机购买页和 B 端云手机商品管理能力：购买页需要在常规版、全新版展示宣传图、宣传专区、特价专区和限时购买列表；后台需要支持商品区、服务时长、排序、库存预警及宣传内容配置；云机侧需要更新 SDK 并固定为 720×1280 画面尺寸。

## 3. 前置条件 / 准备工作

- 准备常规版与全新版购买页访问条件。
- 准备特殊区、普通区、0 元商品及库存不足商品。
- 准备后台管理员账号和宣传图片文件。
- 库存预警场景需要能够等待或触发 20 分钟校验任务。

## 4. 业务范围与不做范围

范围内包括购买页双 Tab 展示、宣传专区、特价专区、限时购买、商品配置、宣传内容配置、库存预警、免费体验时长及云机 SDK/尺寸适配。

本轮不验证支付链路内部扣款实现、云机分配服务内部代码、编辑商品顺序弹窗未明确的规则，以及截图未给出的枚举明细。

## 5. 面向研发的需求拆解

- C 端：常规版和全新版均读取后台宣传内容；特殊区为空时隐藏，存在配置时横排展示且最多 4 个商品；普通区更名为限时购买并竖排展示。
- B 端商品配置：服务时长范围为 0～370 天、0～23 小时且不可同时为 0；特殊区最多 4 个生效商品；盒子内排序为 1～1000 正整数，相同值按创建时间倒序。
- B 端宣传配置：云机类型必须完整且不重复；宣传图片最多 5 张，支持 gif/jpg/jpeg/png，单文件不超过 500k；宣传内容最多 2 条。
- 服务端：库存小于等于预警值时隐藏 C 端商品、阻止云机分配并触发机器人报警。
- 云机能力：更新 SDK，画面尺寸调整为 720×1280。

## 6. 面向测试的验收关注点

- 验证 B 端配置到 C 端展示的跨端一致性。
- 分别验证服务时长、排序值、特殊区数量及宣传图片数量/格式/大小边界。
- 验证宣传图片 1008×160 仅为建议提示，不升级为上传或保存强拦截。
- 验证库存预警任务的隐藏商品、阻断分配和机器人通知三个结果。
- 验证 0 元商品免费体验不进入支付页，且服务时长同时计算天数与小时。

## 7. 数据 / 埋点 / 接口 / 配置要求

- 商品区枚举包括特殊区和普通区。
- 宣传图片来源于盒子管理后台云手机商品管理的编辑宣传内容配置。
- 库存预警按 20 分钟周期校验。
- 免费体验时长需要验证 `duration` 天数和 `hour` 小时共同换算。

## 8. 风险与兼容性

- B 端配置、C 端展示、库存任务和云机分配涉及跨系统状态一致性。
- SDK 更新和 720×1280 尺寸需要真实云机环境验证画面、卡顿及脚本兼容。
- 机器人通知和库存任务需要测试环境具备可观察日志或消息渠道。
