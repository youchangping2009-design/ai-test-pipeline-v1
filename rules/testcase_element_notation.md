# 测试用例元素统一标注规范

## 1. 规则目标

测试用例中的页面、按钮、弹窗、字段、业务值、状态、提示语和技术字段必须尽量使用统一标注。目标不是追求排版形式，而是让关键元素具备明确语义，方便人工评审、AI 生成一致性、自动化脚本映射、strict gate 校验，以及后续 `testcase_bundle.json` 结构化演进。

## 2. 适用范围

本规范适用于正式测试用例中的：

- `testcases/testcases_main.md`
- `testcases/testcases.md`
- 从 testcase 派生的兼容投影

同时建议在 `case_plan.md` / `case_plan.json` 的 `title`、`assertion`、后续可选 `ui_elements` 字段中复用同一套表达。

旧工作项在非 strict 校验下保持兼容；新工作项和显式启用元素标注校验的 strict 交付应遵守本规范。

## 3. 标注总表

| 元素类型 | 标注格式 | 示例 | 说明 |
|---|---|---|---|
| 页面 / Tab / 一级模块 | `[]` | `[商品配置页]`、`[购买页]`、`[宣传内容]Tab` | 表示用户所在页面、模块、Tab |
| 按钮 / 操作入口 | `【】` | `【保存】`、`【新增】`、`【免费体验】` | 表示可点击动作，包括按钮、链接、图标入口、操作栏入口 |
| 弹窗 / 抽屉 / 面板 | `《》` | `《新增商品弹窗》`、`《编辑商品抽屉》` | 表示弹窗、抽屉、浮层、配置面板 |
| 字段 / 表单项 / 列表列 | `“”` | `“商品名称”`、`“价格”`、`“宣传图片”` | 表示表单字段、列表字段、详情字段、筛选字段 |
| 枚举值 / 选项值 / 输入值 | `{}` | `{特殊区}`、`{启用}`、`{0元商品}` | 表示用户选择或输入的业务值 |
| 状态 / 标签 / 结果 | `<>` | `<已生效>`、`<体验中>`、`<保存成功>` | 表示系统状态、标签、结果状态 |
| 提示语 / Toast / 校验文案 | `「」` | `「保存成功」`、`「最多配置4个」` | 表示页面提示、Toast、字段校验文案 |
| 接口 / 参数 / 技术字段 | 反引号 | `` `goodsRegion` ``、`` `saveGoodsRegion` `` | 表示接口名、参数名、技术字段、枚举 code |

## 4. 各类元素定义

### 页面 / Tab / 一级模块：`[]`

用于标注用户所处位置、页面、Tab、一级模块或明显的业务区域。

正确：

- 进入[商品配置页]
- 切换到[宣传内容]Tab
- 在C端[购买页]查看商品卡片

错误：

- 进入商品配置页
- 切换到宣传内容Tab

### 按钮 / 操作入口：`【】`

用于标注可点击动作，包括按钮、链接、图标入口、操作栏入口。

正确：

- 点击【保存】
- 点击【新增】
- 点击操作栏【编辑】

错误：

- 点击保存
- 点击新增入口

### 弹窗 / 抽屉 / 面板：`《》`

用于标注浮层式容器。弹窗、抽屉、面板不得与字段混用同一符号。

正确：

- 在《新增商品弹窗》中填写“商品名称”
- 打开《编辑商品抽屉》

错误：

- 在“新增商品弹窗”中填写“商品名称”

### 字段 / 表单项 / 列表列：`“”`

用于标注用户填写、选择、查看或断言的业务字段。

正确：

- “商品类型”选择{特殊区}
- 列表列“状态”展示为<已启用>

错误：

- 商品类型选择特殊区
- 列表状态展示为已启用

### 枚举值 / 选项值 / 输入值：`{}`

用于标注用户选择或输入的业务值。

正确：

- 将“商品区域”选择为{特殊区}
- 将“价格”填写为{0}

错误：

- 将“商品区域”选择为“特殊区”

### 状态 / 标签 / 结果：`<>`

用于标注系统生成、页面回显或流程流转后的状态。

正确：

- 保存后“状态”展示为<已启用>
- 点击【免费体验】后用户进入<体验中>状态

错误：

- 保存后状态展示为启用

### 提示语 / Toast / 校验文案：`「」`

用于标注页面提示、Toast、字段说明、校验文案。提示语必须独立标注，避免 soft_prompt 被误生成 hard_block。

正确：

- 页面提示「保存成功」
- 上传区域展示「建议尺寸720*1280」

错误：

- 页面提示保存成功
- 上传失败并提示建议尺寸720*1280

### 接口 / 参数 / 技术字段：反引号

用于标注接口名、参数名、技术字段、枚举 code。页面业务字段仍使用 `“”`。

正确：

- 接口 `saveGoodsRegion` 的请求参数 `goodsRegion` 应为 `special`
- 页面字段“商品区域”展示为{特殊区}

错误：

- 接口“saveGoodsRegion”的参数“goodsRegion”应为特殊区

## 5. 标注优先级

同一个词可能在不同上下文中有不同语义，必须按使用场景标注。

| 场景 | 标注 |
|---|---|
| 页面按钮 / 入口 | `【免费体验】` |
| 商品类型选项 | `{免费体验商品}` |
| 用户状态 | `<体验中>` |
| 普通业务能力描述 | 不强制标注，可写“免费体验能力” |

示例：

```text
“商品类型”选择{免费体验商品}
C端[购买页]展示【免费体验】入口
点击【免费体验】后，用户状态变为<体验中>
```

## 6. 正确 / 错误示例

### 示例 1：B端写侧强约束

正确：

```text
进入[商品配置页]，点击【新增】，在《新增商品弹窗》中将“商品区域”选择为{特殊区}，连续配置5个特殊区后点击【保存】，系统阻止保存并提示「特殊区最多配置4个」。
```

错误：

```text
进入商品配置页，点击新增，在“新增商品弹窗”中选择商品区域为特殊区，点击保存后提示特殊区最多配置4个。
```

### 示例 2：软提示展示

正确：

```text
进入[商品配置页]，打开《宣传内容配置弹窗》，查看“宣传图片”上传区域，应展示提示语「建议尺寸720*1280」。
```

注意：这个场景只是提示展示，不应生成“上传失败”或“保存失败”强拦截断言，除非 PRD 明确要求。

### 示例 3：B端配置到C端消费链路

正确：

```text
在[商品配置页]中点击【新增】，在《新增商品弹窗》中将“价格”填写为{0}并点击【保存】。进入C端[购买页]，应展示【免费体验】入口；点击【免费体验】后，用户进入<体验中>状态，且不进入正常支付流程。
```

### 示例 4：列表字段回显

正确：

```text
在[商品配置页]配置“商品名称”为{测试商品A}并点击【保存】后，返回[商品列表]，列表列“商品名称”展示为{测试商品A}，列表列“状态”展示为<已启用>。
```

### 示例 5：接口参数

正确：

```text
在[商品配置页]将“商品区域”选择为{特殊区}并点击【保存】后，接口 `saveGoodsRegion` 的请求参数 `goodsRegion` 应为 `special`，保存成功后列表列“商品区域”展示为{特殊区}。
```

## 7. 不要过度标注

只标注会影响以下事项的关键元素：

- 操作定位
- 页面定位
- 字段填写
- 断言判断
- 状态变化
- 提示语判断
- 接口 / 参数映射
- 自动化脚本定位

普通动词、普通连接词、非关键名词不需要标注。

错误示例：

```text
进入[后台]，点击【进行】，在《系统》中查看“相关内容”。
```

## 8. 与 case_plan 的关系

`case_plan` 仍负责用例计划、来源、断言、验证端和优先级；元素标注规范负责让计划中的关键 UI / 业务元素表达更稳定。

本轮不强制修改 `case_plan` schema。后续可预留：

```json
{
  "ui_elements": [
    {
      "name": "商品配置页",
      "type": "page",
      "notation": "[商品配置页]"
    },
    {
      "name": "保存",
      "type": "button",
      "notation": "【保存】"
    }
  ]
}
```

## 9. 与 testcases_main.md 的关系

`testcases_main.md` 仍是当前主 testcase 真源。正式 testcase 的测试步骤和预期结果应优先使用本规范标注关键元素，同时继续保留 `来源 CasePlan：CP-xxx` 或 `case_plan_id=CP-xxx` 追溯。

## 10. 与 strict gate 的关系

元素标注 lint 当前采用兼容策略：

- 非 strict：输出 warning，不阻塞。
- strict + 显式启用元素标注检查：明显未标注问题转为 error。
- 旧工作项默认不因历史标注问题失败。

显式检查命令：

```bash
/usr/bin/python3 skills/case-generation/scripts/testcase_element_lint.py \
  --input assets/projects/<PROJECT_CODE>/work_items/<WORK_ITEM_ID>/testcases/testcases_main.md \
  --strict
```

也可通过 `validate_work_item.py --check-element-notation` 接入工作项校验。

工作项也可以在 `manifest.json` 中显式启用：

```json
{
  "testcase_element_notation": {
    "enabled": true
  }
}
```

## 11. 与自动化映射的关系

统一标注为自动化映射提供稳定线索：

- `[]` 可映射页面对象或路由。
- `【】` 可映射按钮、链接、图标入口。
- `《》` 可映射弹窗、抽屉、浮层容器。
- `“”` 可映射表单项、列表列、详情字段。
- `{}` 可映射输入值、枚举值或测试数据。
- `<>` 可映射状态断言。
- `「」` 可映射 Toast、错误提示、说明文案。
- 反引号可映射接口、参数、技术字段。
