# 测试用例人工可读表达风格规则

## 1. 规则目标

本规则用于约束正式测试用例的标题、前置条件、测试步骤和预期结果，让用例在保持可追溯、可执行、可校验的同时，更接近测试同学日常可读、可执行、可判断的表达。

本规则是表达层规则，不替代以下硬约束：

- `rules/testcase_element_notation.md` 的元素标注规则。
- `rules/testcase_grouping_rules.md` 的页面与板块分组规则。
- `case_plan_id` / coverage / traceability 追溯要求。
- 单规则单断言、不得脑补强拦截、不得降低 strict gate 的要求。

## 2. 总体原则

### 2.1 先写用户看到什么、做什么、结果是什么

测试用例应优先落到用户可见页面、测试可执行动作和可观察结果。

推荐：

- 确认“广告类型”默认选中{信息流广告}
- 将“广告类型”切换为{搜索广告}后，确认“回调类型”固定为{api}
- 勾选搜索广告后，确认【批量起量】不会对搜索广告生效

不推荐：

- 验证广告类型字段默认值正确
- 验证回调类型字段满足规则
- 验证批量起量能力与过滤逻辑符合预期

### 2.2 保留测试语言，减少审计腔

允许使用“验证 / 核对 / 确认 / 检查”，但标题和步骤不应像规则登记或审计结论。

推荐动词：

- 确认
- 核对
- 检查
- 尝试
- 查看
- 切换
- 勾选
- 提交
- 保存
- 打开
- 搜索
- 对照

谨慎使用：

- 登记
- 映射
- 语义等价
- 收口
- 保持一致语义
- 规则满足
- 结构化规则
- 显式规则
- 断言对象
- 候选项语义集合

### 2.3 抽象结论必须落到可见结果

需求本身不确定时可以保守，但仍要写成测试人员能执行和判断的表达。

推荐：

- 若页面未提供该入口，则记录为通过；若入口仍可点击并提交，则记缺陷
- 若产品提供灰置提示，记录提示文案并确认不能继续配置
- 若当前环境未实现该区域，标记 BLOCKED 并补充当前页面截图

不推荐：

- 不存在上述下线入口语义
- 可出现等价新版位结构
- 与现行一致语义
- 以产品等价文案核验

## 3. 标题表达规则

### 3.1 标题直接说明本条用例要确认的业务结果

推荐标题结构：

```text
确认 + 业务对象 + 操作/条件 + 结果
核对 + 页面/区域 + 字段/入口 + 展示结果
尝试 + 异常操作 + 系统拦截结果
```

推荐：

- 确认“广告类型”默认选中{信息流广告}
- 确认选择{搜索广告}后“回调类型”固定为{api}
- 确认版位区域不再展示【按媒体选择】和【自动版位】
- 尝试批量起量搜索广告时，搜索广告不会进入生效范围
- 确认“智能拓流”默认开启且不能关闭

不推荐：

- 核对广告类型基础属性
- 验证回调类型字段满足规则
- 登记链路前提
- 验证版位模型下线
- 验证批量起量能力与过滤

### 3.2 标题禁止空泛词

标题不得使用“正确 / 正常 / 符合预期 / 页面正常”替代真实业务结果。

不推荐：

- 验证广告类型展示正确
- 验证筛选功能正常
- 验证页面配置符合预期

推荐：

- 确认“广告类型”候选项包含{信息流广告}和{搜索广告}
- 选择{搜索广告}筛选后，列表只展示搜索广告相关数据
- 保存配置后，列表回显刚才填写的配置名称和状态

### 3.3 标题不暴露机器来源

不推荐：

- 按 COV-0970-001 验证广告类型
- 验证 field_property 规则
- 验证 structured_prd 显式规则
- 验证 coverage 矩阵完整性

推荐：

- 确认“广告类型”默认选中{信息流广告}
- 确认“广告类型”候选项包含{搜索广告}

机器来源应保留在备注中，例如：

```text
来源coverage：COV-0970-001；来源 CasePlan：CP-001
```

## 4. 前置条件表达规则

### 4.1 前置条件写测试开始前需要具备什么

推荐：

- 已进入[玩心后台-批创编辑]，并打开【基础信息】区
- 当前账号具备编辑腾讯3.0批创广告的权限
- 已存在一条{信息流广告}和一条{搜索广告}数据
- 当前广告的“游戏类型”可切换为{小游戏}

不推荐：

- 前置条件成立
- 页面可用
- 数据准备完成
- 满足测试条件
- 具备相关测试环境

### 4.2 不确定条件写清楚等待项

推荐：

- 若测试环境暂无搜索广告数据，先由研发或产品提供一条可勾选的搜索广告
- 若页面未开放该入口，本条标记 BLOCKED，并记录当前页面截图
- 若产品未确认拦截文案，只验证入口不可继续提交，不自拟提示语

不推荐：

- 无则记待测
- 由产品定义
- 待确认
- 按实际情况处理

## 5. 测试步骤表达规则

### 5.1 每一步以测试人员动作开头

推荐动作：打开、进入、点击、选择、输入、清空、勾选、取消勾选、展开、搜索、提交、保存、刷新、返回、查看、对照、记录。

推荐：

```text
1. 进入[玩心后台-批创编辑]，打开【基础信息】区
2. 展开“广告类型”下拉框
3. 查看下拉框中的候选项
```

不推荐：

```text
1. 执行广告类型校验
2. 验证候选项规则
3. 判断是否符合需求
```

### 5.2 步骤不要写成纯校验结论

不推荐：

- 确认广告类型正确
- 检查字段满足规则
- 验证页面符合设计

推荐：

- 展开“广告类型”下拉框
- 查看是否同时存在{信息流广告}和{搜索广告}
- 选择{搜索广告}后点击【查询】

### 5.3 复杂规则拆成操作和观察

推荐：

```text
1. 将“广告类型”从{信息流广告}切换为{搜索广告}
2. 返回【广告策略】区查看已选版位
3. 观察切换前选择的版位是否仍被保留
```

不推荐：

```text
1. 切换广告类型并验证依赖字段清空
```

## 6. 预期结果表达规则

### 6.1 预期结果写成可观察结果

推荐：

- “广告类型”默认选中{信息流广告}
- 下拉候选项包含{信息流广告}和{搜索广告}
- “回调类型”展示为{api}，且不能展开或修改
- 【按媒体选择】和【自动版位】不再展示
- 搜索广告不会进入批量起量的生效对象范围

不推荐：

- 字段展示正确
- 规则生效
- 页面正常
- 功能符合预期
- 与结构化规则一致

### 6.2 抽象词必须改成具体判断

不推荐：

- 仅存在或仅展示本期授权值
- 与现行一致语义
- 候选项语义集合等价
- 等价只读收口

推荐：

- 页面只展示{用户增长}，没有其它可选营销目的
- 交互路径与现有“腾讯3.0搜索直投”的关键词编辑路径一致；若有差异，记录差异点
- 设备范围只能选择{不限}或{移动}，没有第三个选项
- 字段展示为只读，用户不能修改为其它值

### 6.3 对不确定实现使用“若...则...”，但必须可执行

推荐：

- 若入口完全不展示，则本条通过
- 若入口展示但置灰，需要有不可操作状态或说明文案
- 若入口可点击并能提交，则本条不通过
- 若产品尚未提供文案，只验证不能继续提交，不新增自拟 Toast 断言

不推荐：

- 具体口径以产品定义为准
- 以产品等价文案核验
- 若实现存在差异则记录
- 按实际实现判断

## 7. 元素标注与口语化的关系

### 7.1 业务字段用中文引号，技术字段用反引号

推荐：

- 查看“广告类型”的默认值
- 将“游戏类型”选择为{小游戏}
- “回调类型”展示为{api}

不推荐：

- 查看 `广告类型` 的默认值
- 将 `游戏类型` 选择为 `小游戏`
- `回调类型` 展示为 `api`

反引号仅用于接口、参数、技术字段：

- 接口 `saveCampaign` 请求参数 `ad_type` 传值为 `search`
- 页面字段“广告类型”展示为{搜索广告}

### 7.2 标注符号不替代自然句子

不推荐：

- [批创页]【基础信息】“广告类型”{搜索广告}

推荐：

- 在[批创页]的【基础信息】区，将“广告类型”选择为{搜索广告}

### 7.3 按钮和入口要写成动作

不推荐：

- 【保存】后成功
- 【批量起量】不可用

推荐：

- 点击【保存】后，页面提示「保存成功」
- 勾选搜索广告后，【批量起量】置灰或提交时自动排除搜索广告

## 8. 常见替换词表

| 当前偏机器/审计表达 | 推荐人工可读表达 |
|---|---|
| 验证xxx满足规则 | 确认xxx按需求展示 / 确认xxx按需求生效 |
| 候选项语义集合等价于 | 候选项只包含 |
| 等价只读收口 | 字段只读，不能修改为其它值 |
| 不出现旧模型入口语义 | 页面不再展示旧入口 |
| 可映射到对应跳转参数 | 点击后进入对应页面 / 打开对应地址 |
| 与现行一致语义 | 与现有页面的操作路径一致 |
| 结构化规则一致 | 与需求中的限制一致 |
| 保持不可编辑态 | 字段不可编辑 |
| 本次保存失败 | 点击【保存】后不能保存成功 |
| 不落库 | 保存后列表/详情中不出现该值 |
| 明确提示需补充字段 | 页面提示该字段必填 |
| 不符合条件的数据不会出现 | 列表中不展示不符合条件的数据 |
| 记录验证路径 | 在备注中记录实际验证方式 |

## 9. 改写示例

### 示例 1：默认值

推荐标题：

```text
确认“广告类型”默认选中{信息流广告}
```

推荐步骤：

```text
1. 进入[玩心后台-批创编辑]，打开【基础信息】区
2. 查看“广告类型”的默认选中值
```

推荐预期：

```text
1. “广告类型”默认选中{信息流广告}
```

### 示例 2：只读字段

推荐标题：

```text
确认选择{搜索广告}后“回调类型”固定为{api}
```

推荐步骤：

```text
1. 在【基础信息】区将“广告类型”选择为{搜索广告}
2. 查看“回调类型”的展示值
3. 尝试展开或修改“回调类型”
```

推荐预期：

```text
1. “回调类型”展示为{api}
2. “回调类型”不可修改，不能切换为其它值
```

### 示例 3：旧入口下线

推荐标题：

```text
确认版位区域不再展示【按媒体选择】和【自动版位】
```

推荐步骤：

```text
1. 进入[玩心后台-批创编辑]，打开【广告策略】区
2. 查看版位相关配置区域
3. 搜索或浏览是否存在【按媒体选择】和【自动版位】
```

推荐预期：

```text
1. 版位区域不展示【按媒体选择】和【自动版位】
2. 用户不能通过其它入口继续配置这两类旧版位能力
```
