# Product Description Patterns

适用场景：当产品需求存在固定描述习惯时，优先复用本模式库，不要临时发挥。

## 1. 字段定义 + 说明表

特征：
- 先在表单 / 弹窗中出现字段
- 后面单独用表格或说明区描述该字段的效果、取值或分支规则

结构化要求：
- 字段主体进入 `field_definitions`
- 说明表进入 `field_rule_tables`
- 表格每一行都要形成可追溯规则
- `pages.sections` 可保留说明表板块用于溯源，但若该表没有独立入口、动作或状态，不要把它建模成独立业务实体
- 在 `modules.features` 层，优先把说明表挂回所属字段所在 feature；`section.feature_names` 应指向字段所属 feature，而不是额外拆一个“查表 feature”

用例要求：
- 至少 1 组 testcase 覆盖该说明表对应的字段语义
- 表格每一行都要被覆盖或被同一条用例显式聚合承接
- 若说明表只是字段效果说明，testcase 默认应落在字段所属表单 / 弹窗 / 业务 feature 下，验证“字段枚举 -> 效果 / 附加字段 / 限制”，而不是单独验证“表存在”
- 只有当说明表本身有独立展示、权限、交互或布局要求时，才单独生成“说明表展示”类用例

## 2. 状态字段

特征：
- 字段名或展示名包含“状态”
- 明确定义枚举值，如 `关闭 / 开启`

结构化要求：
- 状态字段必须保留 `enum_values`
- 若有状态效果规则，进入 `field_rules`

用例要求：
- testcase 中必须原词保留状态枚举值
- 不得改写成“启用 / 禁用”“有效 / 无效”等同义词

## 3. 条数上限

特征：
- 出现“最多 N 条 / 不允许超过 N 条 / 每 tab 下不超过 N 条”

结构化要求：
- 数量规则进入 `field_rules` 或 `rules`

用例要求：
- 至少覆盖：
  - 上限内保存 / 展示成功
  - 超上限保存失败或不进入展示集合

## 4. 排序弹窗

特征：
- 出现“排序 / 拖动 / 顺位上移 / 新增置前 / 删除后重排”

结构化要求：
- 排序规则拆成：
  - 初始顺序
  - 拖拽排序
  - 删除 / 关闭后顺位变化
  - 新增后位置

用例要求：
- 至少覆盖：
  - 初始顺序
  - 人工拖拽后顺序
  - 删除 / 关闭后的顺位变化
  - 新增后的默认位置

## 5. 触达用户类型表

特征：
- 独立表格描述人群枚举及其附加字段或效果

结构化要求：
- 表体进入 `field_rule_tables`
- 附加字段 / 条件进入 `field_rules`
- 默认视为 `触达用户类型` 字段的语义扩展，而不是新的配置对象
- 若页面中同时存在添加/编辑弹窗，优先挂到 `触达用户类型` 所在的表单 feature

用例要求：
- 表中每种人群至少 1 条覆盖
- 若存在附加字段，例如充值金额区间，必须补充边界 / 异常验证
- 默认生成“触达用户类型枚举效果 / 附加字段联动”类用例，放在所属弹窗或字段语义分组下
- 不要默认生成“查看触达用户类型说明表”这一类把说明表当独立对象的用例

## 6. 列表字段 + 操作区

特征：
- 页面同时出现列表区与操作区
- 操作区包含 `添加 / 编辑 / 复制 / 删除 / 排序` 中的一种或多种
- 系统说明区补充了创建时间、状态、删除限制、排序逻辑

结构化要求：
- 列表字段进入 `field_definitions` 或对应 section 的 `field_refs`
- 操作入口进入 `interactive_entries`
- 删除限制、提示语、顺位变化进入 `rules / field_rules / abnormal_scenarios`

用例要求：
- 至少 1 条 testcase 显式写出列表区字段
- 至少 1 条 testcase 覆盖关键操作入口
- 若存在删除限制，必须单独生成删除校验 testcase
- 不得只在 evidence/structured_prd 承接列表字段，testcase 必须有明确落点

## 7. 添加 / 编辑弹窗字段矩阵

特征：
- 页面存在添加弹窗、编辑弹窗或可推断为同构表单
- 产品文档对字段给出了类型、必填、默认值、来源、可编辑性等说明

结构化要求：
- 字段基础属性进入 `field_definitions`
- 条件展示、条件必填、条件不可编辑进入 `field_rules`
- 若操作区存在“编辑”，尽量显式补 `编辑弹窗` 板块

用例要求：
- testcase 不能只写“必填校验”
- 每个字段至少要在 testcase 中承接到字段名和关键属性
- 编辑态至少覆盖回显、默认值保留和可编辑性差异
- 若存在 `选择活动 / 展示规则 / 状态默认关闭` 等精确属性，必须原词承接

## 8. 关联删除校验

特征：
- 需求中出现“被引用不可删除”“删除前校验引用关系”“删除失败提示”

结构化要求：
- 关联对象进入 `dependencies`
- 删除限制进入 `rules / abnormal_scenarios`
- 若提示语明确，进入 `field_rules` 或显式规则保真点

用例要求：
- 必须单独生成删除限制 testcase
- 预期结果需写清“被引用不能删除”和错误提示，不得改写成泛化“删除失败”

## 9. 红字字段属性标注

特征：
- 字段右侧或下方带红字说明
- 红字中直接给出控件类型、必填、默认值、数据来源、编辑性、content 文案、条件展示规则

结构化要求：
- 基础属性进入 `field_definitions`
- 条件差异、固定 content、精确提示语进入 `field_rules`
- 若同一字段在不同条件下“展示但不可编辑”，不得只写数据来源，必须补 `effect_constraint`

用例要求：
- testcase 必须显式承接字段名和字段属性
- 不得把整组红字压缩为“校验字段规则”

## 10. 列头型列表区

特征：
- 列表区直接给出一整行列头
- 列头包含业务字段 + 元数据字段 + 操作列

结构化要求：
- 列头尽量进入 `visible_elements`
- 能映射为字段的列头尽量进入 `field_definitions`
- 操作列中的 `编辑 / 复用 / 删除` 进入 `interactive_entries`

用例要求：
- 至少 1 条 testcase 显式说明列表区要展示哪些字段
- 至少 1 条 testcase 覆盖操作列行为
